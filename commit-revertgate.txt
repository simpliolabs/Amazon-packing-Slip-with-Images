cache, to stop the push from PATCHing offerless backfilled rows into phantom
"Missing offer" ASINs (the B0GHH4MQ7N incident). But listing_health is INCOMPLETE
for low-traffic / print-on-demand listings, so the gate blanket-skipped all 121
REAL, live children of B0FKDDN44Z — confirmed live via the Listings API and
reproduced in the seller's AUTHENTICATED browser. An unauthenticated cached curl
had masked the bug and made me wrongly believe #263 fixed it.

from "offerless phantom" — both are absent — so any gate keyed on it over-skips
legitimate listings.

it is given (the pre-#260 behavior the seller relied on). notLive is hard-false;
the skip path is now a no-op.
