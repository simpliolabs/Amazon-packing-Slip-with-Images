feat(optimizer): on-demand scoring so any listing's page loads (not just top-50 sellers)

The optimizer only scores the top-50 parents by 30d sales (syncListingContent
reads parent_asin_rollup ORDER BY total_units_30d LIMIT 50). Listings below that
— e.g. 0-unit B0FKDDN44Z (121 healthy children) and B0GCPHGN4J — get no
listing_seo_scores row, so they're absent from the optimizer index and their
/fba/listing/[asin] page reads "not available". Neither Regenerate (which
.update()s listing_seo_scores — a no-op when the row is missing) nor "Sync Now"
(/api/sync = orders only) can create the row, so there was no no-code remedy.

Fix: ensureListingScored(supabase, parentAsin) scores ONE parent from the
listing_content we already have — DB only, no Amazon calls, no Jungle Scout
credits — and upserts its listing_seo_scores row (mirrors the sync's upsert
fields; representative child + 30d units fall back to the first child / 0 when
there's no parent_asin_rollup row). The index GET accepts ?ensure=<asin>: if
that asin isn't already in the ranked result, it scores it on the fly and
appends it. The listing page now passes &ensure=<asin>, so opening ANY listing
scores it and the find() resolves — regardless of sales rank.

Scoped: ensure only runs for an asin NOT already in the top set (no added
latency for top sellers); a never-synced listing with no children returns null
and correctly stays absent (a true 0-live-children ghost). Fixes the
has-children-but-unscored class (B0FKDDN44Z confirmed: 121 live children).
